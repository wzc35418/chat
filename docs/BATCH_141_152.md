# 批次总结：R-263 … R-276（第 141–152 轮）

这 12 轮的主线：**把“能跑”变成“可交接”**——部署、运维、巡检、soak、新鲜度检查、交付验证。功能几乎没加，但每一条都在减少“以后出事说不清”的概率。

## 一、按主题

### 1) 证书与轮换

- `deploy/rotate-certificate.ps1`：保留 `seed.hex` 与数据，只换证书；旧指纹写 `fingerprint-history.txt`（审计）；自动跑包内自检；
- **双指纹轮换窗口**：`PackageE2eSmoke` 的指纹参数支持逗号分隔列表（内核按集合匹配），实测 `pinned 2 certificate(s)` → 发送 accepted → 拉取 applied。

### 2) 可达性与 NAT 的事实

- `presentation/display/EndpointReachability.kt`：按字面 IP 判 Loopback / PrivateNet / CGNAT / Public / Hostname，并给可执行说明（10 条断言）；
- **事实核查**：消息路径走自建 HTTP 节点（不依赖打洞）；iroh P2P 传输层已有显式中继配置并通过 **78 个测试**，但**未接入消息路径**。三处文档的限制条目据此改写——“不能说穿透 NAT”的理由是**没接线、没实测**，不是没代码。

### 3) 运维

- `deploy/inspect-node.ps1`（远程 / 本机双模式）+ `docs/OPS_RUNBOOK.md`（巡检 / 自启 / 日志 / 备份 / 换证书 / 故障对照表 7 条 / 事故处置）；
- 远程实跑 `INSPECT: HEALTHY`；本机实跑正确报出 2 个问题（进程未运行、8443 无监听）并提示开机任务未注册。

### 4) 性能与 soak

- `tools/soak.ps1`：冷启动模式（本机 20 轮 / 公网 10 轮，**100% 成功**；本机 p50 2018 ms，公网 p50 20319 ms）；
- `-Reuse` 稳态模式（同一身份连发）：**本机 144 ms/条**、**公网 4429 ms/条**，各 10 条 100% 成功；拉取 `fetched=22 applied=11 skipped=11`（去重按游标生效）。

### 5) 交付与防错

- `tools/check-artifact-freshness.ps1`：把“旧 jar”事故变成断言（已接入 `verify-remote` / `soak`）；`verify-package` PASS 后 stamp `app.jar`；
- `tools/verify-zip.ps1`：解压**交付的 zip**、校验布局与 exe 哈希、**从解压副本**跑冒烟 → `ZIP CHECK: PASS`；
- `docs/INSTALLER_PLAN.md`：为何无 MSI、联网构建命令、5 项必验、3 个坑。

### 6) 代码收敛与小功能

- 后台自动同步（60 s + 指数退避 + 离线可见，不弹后台错误条）；
- 拉取到新消息弹托盘通知（只说条数、不带正文；不支持则**不假装**）；
- 错误码提取二次收敛：`failureCode` 委托 `projectFailure`，13 处 `codeOf` 归零。

## 二、我在这 12 轮里犯的错

| # | 错误 | 根因 |
| --- | --- | --- |
| 1 | `String.replace` 写 PowerShell，撞上 **`$'` 替换模式** | 文件被吃掉半行；最终整份脚本按行重建 |
| 2 | `verify-all.ps1` 报 `parameter cannot be found: RemoteEndpoint` | `param()` 里中文注释 + **无 BOM**，PS 5.1 按 ANSI 读吞掉参数 |
| 3 | `cmd /c` 拼参数行 → `CommandNotFoundException` | 单引号里包反引号引号，生成字面反引号 |
| 4 | **第 4 次**栽在旧 jar | 改 Kotlin 未重新打包；本轮因此加了新鲜度断言（把教训变成检查） |
| 5 | `verify-package.ps1` 少一个引号 | 用 `String.replace` 拼脚本时手误；`[Parser]::ParseFile` 立刻抓到 |
| 6 | 复原 mtime 时设成**未来 5 分钟** | 自己制造了未来时间，导致 freshness 持续误报 |
| 7 | 移动定时器块时挤掉了 `remember { DesktopLifecycle { … } }` 的闭合括号 | 编译报的是 `@Composable` 上下文错误（625 行），实际坏在括号结构 |
| 8 | 双指纹首跑 NPE | `fetchNodePublicKeyPinned` 只认单指纹 → `nodeKey` 为 null → `nodeKey!!` |

**共同点**：脚本/括号/时间戳这类**结构性问题**，编译器或检查器能抓到，但只要绕过检查就会漏。所以本批次把两件事固化了：`[Parser]::ParseFile` 自检 + 新鲜度断言。
