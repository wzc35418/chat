# 批次总结：R-240 … R-262（第 121–140 轮）

这 20 轮的主线只有一条：**把「跨机器可用」从口号变成证据**，顺带把部署路径修到用户能自己走完。

## 二、按主题

### 1) 部署（用户真实环境：Windows Server）

- `deploy/prepare-node-bundle.ps1`：一键生成部署包（release exe + **SAN=公网 IP** 的自签证书 + 种子 + 启动/开机脚本 + 指纹文件 + 自检脚本）；
- `deploy/verify-bundle.ps1`：**拷贝完整性 + 证书指纹一致性 + 可执行 + 探活**，避免“拷了一半就跑”；
- `deploy/README-WINDOWS.md` / `deploy/README.md`：复制 → 防火墙 → 云安全组 → 启动 → 自检 → 本机验证；
- `tools/watch-remote.ps1`：等端口开，开了自动验证；
- `tools/verify-remote.ps1`：TCP 预检 → 证书 pin → 节点身份 → `tls_info` → 打包产物收发 → **UI 路径** → 错误指纹被拒（7 条断言）。

### 2) 证书生命周期

- 启动自动读 `/v1/tls/info`（R-241）；运行期**每 5 分钟**刷新 + 剩余 <30 天进统一错误条（R-258）；
- 证书与地址不匹配（SAN 不含该 IP）给出**可执行指引**（R-252）；
- 仍未做：**自动续签**（需要人工轮换）。

### 3) 排障闭环

- 应用内「节点连通性自检」：health / node_id / 证书指纹 / tls_info / 延迟（R-251）；
- 自检失败进入统一错误条，映射成稳定码并给建议（R-253）；
- 错误码提取从 **37 处重复 → 1 个函数**（R-259）。

### 4) 发送链路

- 「发送（一步完成）」：prepare → dispatch 合并（R-260）；
- 自动恢复：**只对冻结可重试码**重试，未定结果**强制对账**（R-261）；
- 该路径在公网节点上被 `sendFlowSmoke` + 远程断言证明（R-262）。

## 五、仍然不做的（诚实清单）

1. **NAT 打洞 / 中继**：当前只支持**直连**公网 IP；对称 NAT 下不可用；
2. **证书自动续签 / OCSP**：只有告警与人工轮换；
3. **安装器（MSI）**：离线环境无法拉 WiX，只有 app-image + zip；
4. **后台通知 / 托盘常驻**：应用关掉就不再收；
5. **非 Windows 平台**：凭据库与路径只有 Windows 实现；
6. **`AppFacade` 完整收敛**：本轮只做了错误码与发送链路的收敛，面板仍各自调 service；
7. **soak / 压测 / 长期稳定性**：没有连续运行数据。

## 六、下一步优先级

1. NAT 打洞（iroh 已有依赖，缺的是联调环境与策略）；
2. 证书自动轮换（含信任列表批量分发）；
3. `AppFacade` 收敛（面板 40+ 处理器 → 少数命令）；
4. 安装器 + 后台通知；
5. macOS/Linux 凭据库。
