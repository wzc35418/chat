# 两台真机通过公网节点配对：操作单（6 步 + 记录表）

> 目的：补上唯一缺的硬证据——**两台机器、真实公网、真实配对**。
> 全程不需要改代码；每一步都有明确的成功/失败判据。

## 零、准备

| 项 | 值 |
| --- | --- |
| 应用 | `build\dist\app-image\Chat\Chat.exe`（**版本标记应为 `· R-328`**；若不同请先重建） |
| 节点 | `https://106.54.223.171:8443` |
| node_id | `node-public` |
| 证书指纹 | `13be2f93162bd121cba6a91d4e05c22900dcc06abcd92cf843bd5ed772b8a053` |
| 通讯方式 | A 与 B 之间用任意渠道互发文本（微信/邮件都行，**只发文本，不发文件**） |

两台机器都先做同一件事：**关掉所有 Chat 窗口**，再打开 `Chat.exe`。

## 第 1 步：两边配置节点（各做一次）

顶栏「设置」→ 填：地址 / `node-public` / 公钥留空 / **证书指纹**（上面那串）→ 保存。

- ✅ 成功判据：顶栏显示 `https://106.54.223.171:8443 · R-328`；提示 `节点配置已保存`
- ❌ 失败判据：保存后仍提示旧地址 → 说明没点「保存」

## 第 2 步：两边跑「自检」（各做一次，这是关键门禁）

顶栏「自检」→ 应该 **全是 PASS**，12 项左右：`cert_fingerprint / health / node_id / tls_info / latency / identity / group / store / clipboard / data_dir / disk_space / node_port`。

- ✅ 成功判据：`自检通过（N 项网络检查 + 4 项环境检查）`
- ❌ 常见失败： `cert_fingerprint 不一致` → 服务端换过证书；`node_port 连不上` → 防火墙/进程
- 需要给开发者的话：把 `%USERPROFILE%\.chat-desktop\diagnose-<时间戳>.txt` 发出来

## 第 3 步：A 生成邀请口令，B 接受（加好友）

**A**：联系人 → 「生成邀请」→ 提示行出现 `邀请口令（24 小时有效）：inv1.…` → 点「**复制提示**」→ 发给 B。
**B**：联系人 → 「接受邀请」→ 粘贴 → 「预览」（应显示邀请人与过期时间）→ 「接受」。

- ✅ 成功判据：B 的提示 `已加入联系人：…（requested，可发送=false）`，联系人列表出现 A
- ❌ 失败判据：`FAIL WELCOME_NOT_AUTHORIZED` / 过期 / `INVALID_INPUT` —— 把原文发出来

> 说明：联系人是**单向**的。A 想也看到 B，需要用 B 的邀请反向做一次。这一步不影响后面建群。

## 第 4 步：A 导出 KeyPackage，发给 B

**A**：顶栏「配对」→「① 导出我的 KeyPackage」→「复制我的 KeyPackage」→ 发给 B。

- ✅ 成功判据：结果区出现 `PASS 已导出我的 KeyPackage（发给对方）`，文本框有一大段 `chat-kp-v1` 开头的文本
- ⚠️ 注意：**不要关掉这个对话框**，也别重启应用——KeyPackage 的私钥材料在内存里，关了就要重来

## 第 5 步：B 建群并回传邀请包

**B**：顶栏「配对」→ 粘贴 A 的 KeyPackage → 「② 用对方 KeyPackage 建群 → 生成邀请包」→「复制邀请包」→ 发给 A。

- ✅ 成功判据：结果区 `PASS 已建群并生成邀请包（发给对方）`；B 的群组页出现一个新群（epoch 1，成员 2）
- ❌ 失败判据：`FAIL 建群失败：…`（会带稳定原因）

## 第 6 步：A 用邀请包入群，然后双方互发消息

**A**：顶栏「配对」→ 粘贴邀请包 → 「③ 用邀请包入群」。

- ✅ 成功判据：结果区 `PASS 已入群：grp:1:… epoch=1`；A 的群组页出现**同名群**，epoch 与 B 相同
- 然后：A 发一条消息 → **B 点「同步」（或等 30 秒自动同步）→ B 应看到该消息**
- 反向再发一条，同样验证

## 已知会失败的地方（提前说明，避免误判）

1. **配对中途关应用** → 必须从第 4 步重来（KeyPackage 是一次性的）；
2. **两台机器时间差很大** → 邀请口令有 24 小时有效期，超时会 `过期`；
3. **B 建群后 A 一直不入群** → 邀请包可以重复粘贴，不会重复建群；
4. **消息对方看不到** → 先确认两端「群组」页 epoch 相同；再看自检的 `node_port`/`health`；
5. **附件仍不可用**（内核未接上传），发文件不会有反应，这是已知缺口，不是这次要验的。

## 这次验证能证明什么 / 不能证明什么

**能证明**：两台真实机器、经真实公网节点、完成加好友 + 建群 + 入群 + 双向消息。
**不能证明**：长稳（几小时）、并发（多人同时）、断电/断网恢复、安装器/后台常驻。
