# 消息 Markdown 规格（展示与输入）

状态：展示层已实现（2026-10-18，DS-12）。实现位置：
`shared/presentation/src/commonMain/kotlin/chat/presentation/display/MarkdownModel.kt`（解析与输入命令）与
`shared/ui/src/commonMain/kotlin/chat/ui/MarkdownText.kt`（Compose 渲染）。

## 1. 为什么是“子集”

消息正文在正式协议里仍然是**纯文本**（`MessageContent.Text`）。Markdown 只在展示层解析，不改变线协议、不改变存储、不引入 HTML 或脚本执行。因此：

- 收发两端保存的都是原始 Markdown 源码；
- 任何客户端都可以退回纯文本显示，不会丢失可读内容；
- 渲染结果永远由本地解析器决定，对端无法通过正文注入界面元素。

## 2. 已支持的语法

| 语法 | 说明 |
|---|---|
| `# 标题` ~ `###### 标题` | 1–6 级标题 |
| `- 项目` / `* 项目` / `+ 项目` | 无序列表 |
| `1. 项目` / `1) 项目` | 有序列表（保留起始序号） |
| `> 引用` | 引用行（单层，不递归嵌套） |
| `---` / `***` / `___` | 分隔线 |
| 三反引号或三波浪线围栏 | 代码块（可带语言标注，内容原样显示） |
| 单反引号 | 行内代码 |
| `**粗体**` / `__粗体__` | 粗体 |
| `*斜体*` / `_斜体_` | 斜体 |
| `~~删除线~~` | 删除线 |
| `[文字](https://…)` | 链接（见第 4 节限制） |
| `\*` 等 | 反斜杠转义 |

## 3. 明确不支持的语法

不解析、也不假装支持：原始 HTML、表格、任务列表、脚注、图片、上标下标、内嵌公式、自动链接（裸 URL 不自动变链接）、嵌套引用与嵌套列表续行。

未知语法一律按**普通文字**显示，绝不吞掉用户内容。

## 4. 安全规则（强制）

1. **不解析 HTML**：`<script>`、`<img onerror=…>` 等只作为文字出现；展示模型里没有 HTML 节点，界面也没有 WebView。
2. **链接协议白名单**：只承认 `http://`、`https://`、`mailto:`。`javascript:`、`data:`、`file:` 等降级为不可点击文字，并显示“链接未启用：原因”。相对路径与锚点同样不可点击。
3. **链接当前不可点击**：正式“用系统浏览器打开链接”的平台能力尚未接入，界面只显示链接文字与地址（地址可复制），避免出现点了没反应的假按钮。
4. **上限**（`MarkdownLimits`）：输入 8192 字符、块 200、行内节点 600、嵌套深度 3、代码块 200 行 / 2000 字符、链接 512 字符、语言标注 32 字符。超限有界截断并显示“内容过长，已省略其余部分”。
5. **控制字符清理**：ISO 控制字符、双向文本控制符（U+202A–202E、U+2066–2069、U+200E/200F）在进入模型前移除，避免视觉欺骗。
6. **空内容回退**：解析不出任何块时显示“（空消息）”，界面不会出现空白气泡。

## 5. 输入支持

样例发送框（预览）已提供：

- 格式工具栏：粗体、斜体、删除线、代码、链接。对当前选区做包裹；空选区插入占位文字并**选中占位文字**，可直接改写；
- 预览开关：编辑 / 渲染预览切换；
- UTF-8 字节计数与 8192 字节上限提示，超限不允许发送；
- 输入命令是纯函数（`applyMarkdownCommand`），可测试，不写入正式状态。

尚未实现（需要正式发送框接入后再做）：自动续行列表、快捷键（Ctrl+B 等）、粘贴富文本降级为 Markdown、草稿持久化。
