# 口令加好友与桌面聊天界面设计

状态：产品与交互设计，尚未接入真实联系人服务。适用范围：第一版可信联系人私聊；桌面端优先，窄屏沿用单栏导航。

依据：[MVP](MVP.md)、[身份与联系人契约](../implementation/identity.md)、[会话契约](../implementation/core.md)、[界面层契约](../implementation/presentation.md)。[桌面界面稿](CONTACT_INVITE_DESKTOP.svg)展示布局与交互入口，示例姓名、消息均为设计数据。

## 1. 产品规则

用户在“加好友”中粘贴对方分享的**加好友口令**。口令是一次性联系人邀请字符串，不是账户登录密码，也不是任意用户可设置的短密码。分享方可在“我的口令”中生成并复制，默认 24 小时有效；过期、撤销或使用后需要重新生成。展示口令时按组分段便于核对，复制结果保留完整原文，不因界面换行修改内容。

口令内容遵循 `create_contact_invite` 契约：版本、邀请 ID、签发者账户身份与公钥指纹、节点提示、`contact-request` 范围的受限能力、到期时间及签名。具体编码长度由协议确定，界面不承诺固定字符数。口令不包含私钥、聊天记录或可用于群管理的能力。服务端只负责受限投递、期限与一次性消费，不能替用户建立信任。

分享方与输入方都可以看到对方的昵称、账户 ID 缩写、节点与指纹。昵称只作展示，不能用于验证身份。首次接触时建议通过独立渠道比对指纹；指纹或既有凭据变化时必须停在明确的警告状态，不能用新值静默覆盖。

## 2. 用户流程

| 阶段 | 输入方看到的状态 | 分享方看到的状态 | 允许的动作 |
| --- | --- | --- | --- |
| 生成 | — | “我的口令”，到期时间、复制、重新生成/撤销 | 分享口令 |
| 粘贴并校验 | 口令输入框；校验后展示身份、节点、指纹 | 尚无变化 | 核对后发送请求 |
| 请求待发送/待确认 | “请求已保存，等待对方确认”；离线时显示“待联网发送” | “好友申请”中显示请求与指纹 | 取消本地待发、接受或拒绝 |
| 本端确认、对端未完成 | “等待对方完成确认” | 相应等待状态 | 查看状态，不开放正式聊天 |
| 双方完成 | 好友进入左栏，点选进入右侧私聊 | 同左 | 发消息、查看指纹 |
| 失效/异常 | 明确错误与重试指引 | 不错误显示为已接受 | 重新获取口令或核验身份 |

“发送请求”调用 `accept_contact_invite(encoded)`；它只建立待确认请求。接受申请调用 `confirm_contact(request_id)`，且用户必须先看到并确认指纹。只有双方能力握手完成、联系人状态为 `accepted` 时，才允许调用 `open_direct`。网络离线时不能把本地已确认显示为对端已确认，也不能出现可发送的正式聊天输入框。

同一口令重复粘贴返回已有请求，不产生重复申请；过期/已使用/签名不合法分别提示。对已存在好友，提示“已是好友”并打开会话；若同一账户的指纹与已固定记录冲突，进入“身份变化”警告，阻止继续。口令输入限制长度与字符集，敏感原文不进入日志、分析事件或错误详情；对外错误不暴露可被枚举的账户信息。

## 3. 桌面布局

主窗口推荐最小宽度 900 dp。左栏固定约 300 dp，右侧自适应。左栏从上到下为应用与当前账户、搜索框、“加好友”主按钮、“好友申请”入口及待处理数、好友列表。好友行显示头像、备注或昵称、最近消息摘要与时间；信任异常以醒目标识覆盖在线状态。搜索只过滤本地已接受好友，不能用昵称搜索陌生账户。

右栏在未选好友时显示空态：“选择一位好友开始聊天”，提供“添加好友”入口。选中好友后依次显示联系人标题与身份核验入口、滚动消息区、发送状态与输入区。输入区只对 `accepted` 联系人启用；待申请/身份异常时显示对应说明和处理按钮。消息状态区分“待发送 / 已接受 / 已送达 / 失败”，不把本地入队当作已送达。

“加好友”点击后使用居中对话框：

1. **输入口令**：多行粘贴框、清晰的格式/有效期说明、“验证口令”按钮。输入前不显示陌生人资料。
2. **核对身份**：昵称、账户 ID 缩写、节点、完整可复制指纹；“发送好友申请”需要显式点击。对指纹变化使用单独阻断警告，不提供普通的继续按钮。
3. **请求结果**：显示待联网/等待确认/已接受等真实状态，提供关闭与查看申请。弹窗关闭不删除已持久化的请求。

“我的口令”可由左栏账户菜单打开。默认只显示到期时间和复制按钮，点击“显示”才展示完整口令；重新生成后旧口令显式撤销。复制成功给短暂反馈。分享口令属于用户主动操作，不自动上传到通讯录或公共目录。

窄屏（小于 720 dp）一次只显示好友列表或会话，顶部返回按钮切换；加好友对话框改为占满可用宽度。桌面布局中的好友列表与会话共享同一业务状态，不维护两套联系人副本。

## 4. 状态与实现边界

界面层需要 `ContactListState`、`ContactInviteUiState`、`ContactRequestState` 与当前会话状态。列表只消费核心返回的稳定账户/会话 ID；请求状态至少区分 `validating`、`readyToRequest`、`queuedOffline`、`waitingForPeer`、`waitingForBothSides`、`accepted`、`expired`、`identityChanged`、`failed`。异步查询带代次，切换好友后旧响应不得覆盖当前会话。

实现顺序：先完成身份服务的邀请生成、解码与确认，以及本地请求/outbox 持久化；再通过 core-api/bridge 暴露状态与事件；然后接入 presentation 和共享 Compose UI。当前仓库的 P0 `P0Presenter` 只连接同进程 Alice/Bob，既无正式账户也无联系人存储，不能据此宣称口令加好友已可用。

## 5. 验收场景

- 生成、复制、粘贴同一口令，双方确认后好友只出现一次，并能打开私聊。
- 过期、撤销、重复使用和篡改口令均不能产生已接受联系人。
- 离线提交保留申请，联网后恢复；在对方未确认前发送框始终禁用。
- 原有好友指纹改变时显示阻断警告，不覆盖本地信任锚。
- 900 dp 以上桌面保持左好友列表、右聊天窗口；窄屏导航可返回列表，切换会话不串消息。
- 错误提示与日志均不泄漏完整口令或能力令牌。
