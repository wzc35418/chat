# ADR 0003-crypto-storage: MLS与统一事务存储

状态：待决策。日期：2026-10-18。

待比较 provider API、缓存失效、pending分支恢复、系统保护和全库加密方案；必须附 C01..C09 结果。

P0 实验补充（2026-10-18）：已使用 OpenMLS 0.9.1 / RustCrypto 0.6.0 默认内存 provider 跑通真实 KeyPackage、Welcome 和双向消息。篡改应用密文的测试观察到接收 secret 可能在验证失败后已被消费，原始合法密文随后也无法处理；因此仍需验证错误路径的 provider 写入和事务回滚/缓存失效。本次只为内存 P0 原型采纳“出错后禁止继续使用会话”，没有采纳生产持久化方案。证据及未完成项见 [P0 报告](../P0.md)。

P0-03 候选方案实验（2026-10-18）：`openmls_sqlite_storage 0.3.0` 借用 `rusqlite 0.37.0` 的同一连接；每次从 SQLite 加载群状态，在短事务中完成 OpenMLS 写入与固定密文/outbox 或 inbox 写入。异常/SQL 错误后丢弃群对象并重新加载。Windows 子进程 `abort()` 的发送/接收 6 个断点和拒绝密文回滚用例通过，见 [实测记录](../P0_PERSISTENCE.md)。这支持单库事务候选，但**未采纳为生产决策**：完整 C01..C09、pending Commit、节点对账、加密 DB/WAL、三端与断电验证仍缺失。

同日续验：T1 的意图/准备任务和 T1→T2 状态更新新增 5 个 `abort()` 断点，验证 commit 前无半记录、commit 后可恢复同一意图与密文。仍需将试验表迁入正式 schema、验证群并发与后续 C05/C07-C09；独立试验不改变生产方案待决策状态。

决策模板：背景、候选与官方证据、选择、代价、失败替代方案、验证命令/设备/实际结果、影响函数与回滚策略。没有填写证据前不得标已采纳。
